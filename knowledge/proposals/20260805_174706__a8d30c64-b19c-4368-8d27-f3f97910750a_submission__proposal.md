## Candidate reusable patterns

1. **V6 + PR test migration (accept-risk, not relocate-by-default)**  
   When upstream PR *migrates* existing Jest/unit suites (old API assertions → new API), `tests.patch` will delete lines in pre-existing test files. Static-check V6 treats that as FIXABLE “p2p vandalism,” but for a faithful Harborization it is often the real PR test delta. Prefer documenting `preflight --accept-risk` with: (a) which suites migrated, (b) why new-file-only relocation would rewrite PR test layout beyond natural scope, (c) oracle 1.0 + NOP 0.0 already green on that patch. Do **not** use accept-risk for other FIXABLE ids (V7, D2, PH1, etc.). Framework: `ACCEPT_RISK_STATIC_FIXABLE_IDS = {V6}` demotes only V6 under `--accept-risk`.

2. **Jest Harbor oracle path ≠ pytest helper**  
   `local_oracle_nop.py` assumes pytest. Node/Jest Harbor tasks fail with `No module named pytest`. Authoritative Executed evidence: Docker build + `bash /solution/solve.sh` + `bash /tests/test.sh`, then `record-validation` from `reward.txt`.

3. **judge_prep Jest fullName vs short `it()` title**  
   Bipartite map may mark short `it('…')` titles UNGRADED / allow_extra while `config.json` fail_to_pass lists Jest fullNames ending with the same title. Treat as join artifact: confirm harbor report / `passed_required_tests`, then `PROMOTE_F2P` or `explained` in `judge_prep_decisions.json` — do not delete working coverage.
